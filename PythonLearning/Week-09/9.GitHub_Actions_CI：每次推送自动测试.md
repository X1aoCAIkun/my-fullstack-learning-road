除了本地的 pytest 对包进行检查，但是这还是基于本地环境的检查；而 GitHub Actions CI则是每次只根据包的依赖，自动对包进行检查

# 这个文件下写 CI 配置
.github/workflows/test.yml:

# 流水线名字
name: test
on:             # 什么时候触发 CI
  push:         # 向 main 分支 push 代码时
    branches: [main]
  pull_request:       # 进行 PR 请求时

# 任务组，任务组中有一个叫 test 的任务
jobs:
  test:
    runs-on: ubuntu-latest   # 在Github提供的最新版Ubuntu云虚拟机上跑
    strategy:
      matrix:
        python: ["3.10", "3.11", "3.12"]    
    steps:          # 任务执行步骤
    # 使用action插件，checkout是将代码下载到云端虚拟机
      - uses: actions/checkout@v4
    # 安装 uv 包管理器
      - name: Install uv
        uses: astral-sh/setup-uv@v3
    # 安装对应的 python 版本
      - name: Setup Python ${{ matrix.python }}
        run: uv python install ${{ matrix.python }}
    # 读取 pyproject.toml，以及安装所有依赖
      - name: Install deps
        run: uv sync --all-extras
    # 进行 ruff 检查
      - name: Lint
        run: uv run ruff check .
    # 进行 mypy 检查
      - name: Type check
        run: uv run mypy src
    # 进行 pytest 检查
      - name: Test
        run: uv run pytest --cov=mytodo

# 这样每次 git push 或开 PR ，GitHub会自动在3个Python版本下跑全套检查，全部绿钩才能合并
