明确了为什么要工程化以及工程化与非工程化的区别之后，接下来开始学习如何工程化
首先从项目（结构）目录说起
flat layout（扁平布局）
mytodo/
├── pyproject.toml
├── README.md
├── mytodo.py
└── tests/
这种布局适用于简单的小项目，但是容易把测试文件、配置文件和源码混再一起，打包容易出问题（因为这三种文件是同一类型文件）

src layout（src布局）
mytodo/
├── pyproject.toml
├── README.md
├── LICENSE
├── src/
│   └── mytodo/
│       ├── __init__.py
│       ├── core.py
│       └── cli.py
└── tests/
    └── test_core.py
这种布局工业界推荐的，源码和测试、配置文件严格分开，打包更安全，避免误打包不需要的文件，是现在 Python工程 标准写法

“ 划重点 ”：用 src layout 的好处是----绝不会意外 import 到当前目录的代码，必须 pip install -e . 后才能 import，强制你像“其他用户”一样用自己的包
